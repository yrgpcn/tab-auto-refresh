# 0002：恢复任务按完整 URL 身份认领

日期：2026-10-11  
状态：已采纳（Chat 设计裁决，Issue #11）

## 决策

浏览器启动或扩展安装恢复任务时，只有标准 URL 解析后完整地址相同，才将现有标签页认领给任务。完整地址包括路径、查询参数和 hash。不同深链即使 origin 与 pathname 一样，也属于不同监控目标；现场页面不能覆盖任务保存的目标 URL。等待期结束仍无精确候选时，恢复按任务中保存的完整 URL 重开。

规范化仅采用标准 `URL` 解析带来的规范形式，例如移除默认端口、解析点段；不删除 query、hash、尾斜杠，也不重排参数。

运行中的合法站内导航是另一种语义，仍由现有任务 URL 跟随规则处理。外发通知与 Webhook 的 URL 继续只保留 origin 和 pathname，避免 query/hash 中的签名或令牌泄漏。

## 取舍

严格恢复认领避免同路径的不同 query/hash 深链错绑并静默改写监控目标。遇到网站重定向、规范化或动态参数改变时，可能无法复用恢复出的标签页，等待后会按保存的目标 URL 重开，用户可能看到额外标签页。不能用“当前只有一个候选”作为放宽条件，因为它仍不能证明候选页是正确的监控对象。

若真实 Chrome 验收显示常见登录跳转导致重复开页，或破坏 Cookie 恢复屏障，应带着复现证据交 Chat 决定是否调整策略；实现不得自行恢复 pathname-only fallback。

## 验证边界

回归测试覆盖完整 URL 匹配、同路径深链冲突、候选等待、原目标保留、合法站内导航与外发裁剪。代码和 CI 通过后，使用隔离 profile 的 Chrome for Testing 验证重启恢复；自动化测试不替代该真机验收。
