# 决策记录

Project Orchestrator 迁移后的长期、跨任务决策写在本目录。

## 何时写 Decision

适合记录：

- 会长期约束多个功能/模块的架构选择；
- 安全/隐私/许可证边界；
- 发布、兼容或状态模型的持久规则；
- 替代了旧权威来源或旧决策的治理变化。

普通实现细节、一次性修复和当前进度留在 Issue / PR，不需要 Decision。

迁移前的大量设计理由原本散在 `AGENTS.md`，完整历史可从基线提交 `0a2b28873113451fe7f4d4b265049c89aa9aac8a` 追溯；未来新增决策不要再把 `AGENTS.md` 扩成项目记忆正文。
