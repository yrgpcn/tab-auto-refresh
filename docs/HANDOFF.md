# Handoff 协议

跨 Chat / WorkBuddy / Codex 交接时，不复制整段聊天；在 Issue / PR 中留下最小可执行上下文。

## 必需字段

### 目标

要完成什么可验证结果。

### 当前上下文

相关 Issue / PR、涉及模块、已完成工作、当前失败证据。

### 必须保留的约束

列出会改变实现选择的架构、安全、兼容、许可证、i18n、发布或测试边界。

### 授权边界

明确允许改哪些文件/行为，以及哪些动作（例如真机操作、发布、tag）尚未授权。

### 验收

给出测试命令、真机步骤或可观察结果。

### 结果位置

分支、提交、PR、Issue 评论或日志位置。

## 路由

- Chat：范围、架构、安全、发布与决策；
- WorkBuddy：跨工具、多步骤验证、真机协调、状态同步；
- Codex：实现、测试、调试、重构、代码 Review。

出现权限缺失、目标歧义、产品行为取舍、发布授权不明确时停止实现并路由回 Chat，而不是自行扩范围。
