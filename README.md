# Tab Auto Refresh

轻量的 Chrome 标签页定时刷新扩展。为普通网页标签设置自动刷新间隔，支持全局暂停、快捷键与中英文界面。浏览器自带的页面（设置页、扩展页那一类）开不了任务，弹窗会当场说明。

## 刷新

- 预设间隔：30 秒 / 1 分钟 / 2 分钟 / 5 分钟 / 10 分钟 / 30 分钟 / 1 小时
- 自定义间隔：任意秒数，最小 30 秒
- 右键菜单：在网页空白处或标签页上右键，从同一套预设里挑一个间隔，或直接停止该页的任务（自定义秒数只在弹窗里填）
- 快捷键：`Alt+Shift+R` 开关当前标签页的定时刷新，沿用上次设置的间隔；顺带解除全局暂停。浏览器内部页面按不了，快捷键在这种情况下没有反馈
- 立即刷新：每条任务那一行有一个"立即刷新"，手动触发一次，不看当前是不是它的刷新点；当前页面还没有任务时，这个按钮不在
- 忽略缓存：可选 Ctrl+F5 强制刷新，默认开启
- 全局暂停：一键暂停或恢复全部任务，角标同步显示。暂停只停自动刷新，静默心跳与后台保活照常跑，所以按最后请求计时的会话不会因为这个暂停而过期；按最后一次交互计时的会话也照常由保活动一下，只是刷新本身停了。要留意暂停期间页面不再加载，关键词检测与验证墙探测这段时间一起停摆
- 跳过休眠：可选不唤醒已被浏览器丢弃的标签页。打开之后，那种页面到点直接跳过这一拍，一直到你自己点开它为止；这期间只有静默心跳在续会话
- 持久化：任务记在本机，浏览器重启后自动接回原来的标签页；接不回的按记录的网址重开。只记着间隔、没记网址的旧任务（1.4.3 及更早建的）在重启时会被淘汰，那种淘汰不通知

## 盯住登录态

- 登录保持（默认关闭）：备份站点 cookie（含父域 SSO 票据），浏览器重启后自动恢复登录态。采集范围以该站点的注册域为界，公共后缀不会被当成站点，所以读不到无关站点的票据。备份在本机明文存储，见[安全说明](#安全说明)
- 后台保活（默认开启）：向监控页面注入模拟鼠标键盘活动，延缓按用户交互计时的服务器端过期
- 静默心跳（默认开启）：每 4 分钟向监控地址发一次带 cookie 的后台请求，不重载页面、不打扰阅读，专门续住按最后请求计时的会话
- 防系统休眠（默认关闭）：有任务运行时阻止电脑因闲置而睡眠。笔记本电池场景慎用
- 会话失效检测：两条各自独立的通道，各要连续两次采样才确认。状态通道（只在上面那个登录保持开着时才跑）看 cookie 备份里该站点的登录票据从有到无，确认后冻结那一站的备份（不再把好端端的存档覆盖成空的）并通知；行为通道看页面落到登录页、心跳被重定向到登录页或回 401/403，确认后同样通知，另外还点亮角标的红 `!`，并在该页重新登录上之后自动把这条通知收掉。两条通道各自按同一个 6 小时窗口节流，互不相通，而状态通道不碰角标，所以纯靠票据消失识别出来的那次掉线，角标不会变红、通知也得手动点掉

能救与救不了：服务器端踢下线通常按最后一次交互、最后一次请求、或登录后的绝对时长之一计时。前两种分别由后台保活与静默心跳续住，第三种任何手段都救不了。前提与失效场景见[使用边界](#使用边界与验证)。

## 通知

- Webhook（默认关闭）：会话掉线、关键词命中、任务自动停止、任务自动暂停以 JSON POST 推给你，另加一种你手点"发送测试"时发出的 test 事件。Discord / Slack 直接出可读文案；ntfy 能送达，正文是原始 JSON 文本；Telegram 的机器人接口要求载荷里带 chat_id 这个字段，这份 JSON 没有它，所以直连机器人地址会被拒，要用 Telegram 得架一层自己的转发
- 微信直连（默认关闭）：扩展直接调腾讯官方接口推模板消息，不经中继服务器、也不用第三方推送服务，手机不用装 App。填入四项凭据：appID、appsecret、openid 在微信"公众平台接口测试账号"页扫码拿到（免资质、免费），模板 ID 在同一页面新建测试模板后复制。与 Webhook 共用"通知哪些事件"的勾选，配置步骤见 `tab-auto-refresh/wechat-setup.html`，弹窗里有直达
- 两种通知都可以只发你勾的那几类事件，各自有独立的"发送测试"。测试按钮不受事件勾选约束，微信那一颗还要先勾上总开关才露出来
- 微信卡片文案是压缩过的：平台规定单个字段最多 20 个字且不能换行，所以标题是「事件 · 站点」（站点名放不下时整段省掉，只剩事件名）、正文是一句话结论。点击卡片的跳转链接给的是域名加路径，查询参数照旧剪掉；会话掉线与测试这两类卡片根本没有链接
- 弹窗的状态行：webhook 那边填了地址、微信那边勾了开关，才各出现一行状态（只填凭据没勾开关不会有微信那一行）。地址非法给红字，否则显示最近一次投递的结果。失败会点名该去哪改：请求根本没到、接收端不认这个载荷、地址已失效、没权限、被限流、服务端出错，还有 HTTP 回 200 而接收端在正文里说"没有这个 hook"这一类。投递结果只存在本机，不进 `chrome.storage.sync`，不跨设备同步
- 载荷内容：事件类型与时间戳、站点主机名、可读正文，有页面地址的这几类事件带域名加路径（查询参数与井号后面的一段一律剪掉），关键词监控还会带上你填的词。会话掉线那条只有主机名，没有页面地址。见[安全说明](#安全说明)

## 盯一个页面

- 关键词监控（可选）：建任务时填关键词，逗号或换行分隔，最多 10 个、每个最长 100 字，多填的和重复的被丢掉（重复按不区分大小写判）。页面加载后立即查一次，没命中再隔 3 秒、10 秒各补一次，SPA 迟渲染也等得到；iframe 里的文字同样算正文，只是个别站点不让脚本进子框架，那一刻只能读顶层。命中即发系统通知，默认命中后停掉任务，勾选"命中后继续监控"则持续盯守，只有新出现的词才再通知一次。弹窗会按当前页面这条任务回填已填的关键词、是否继续盯守和它实际用的间隔，改它们不必先停掉再重开
- 异常自动暂停：页面持续返回错误（5xx 或 404，连续两次心跳）或出现人机验证墙（连续三次加载探到）时暂停该任务并通知，角标显示 `⚠`。错误页靠心跳兜着，回到 2xx 自动继续，所以这一半要静默心跳开着才成立；验证墙的解除依赖页面再次加载并探不到墙，只有页面一直不跳转才要手动点恢复。墙只看页面标题与足够大的验证服务子框架，不扫正文，因为正文里的"验证码"是日常词。嵌在 iframe 里的整页挑战能检出，挂件尺寸验证框被视口地板挡掉；普通页面只加载 reCAPTCHA 等验证脚本不会单独判墙。默认开启，可在弹窗的"验证墙保护"里关闭；关掉后会停止探测并恢复因验证墙自动暂停的任务
- 尊重你的操作（默认开启）：你在页面上真实操作的 60 秒内跳过刷新，不打断填表和阅读；保活注入的模拟活动不会被误判成你的操作。第二条判据兜底：这一页是你当前窗口里正在看的那个标签页、而且那个窗口确实在前台时也跳过，所以注入失败的页面（受限页、站点权限）也不会当着你面反复重载——反过来说，你盯着某页一秒都没动，那一拍也会被记成"你在操作"。认不出焦点窗口时按"没在看"处理，宁可多刷一次也绝不变成永不刷新。到点被跳过时任务行会写出那一次的原因（只有"你在操作""休眠中"这两种会写在行上，全局暂停与异常自动暂停不写，那两件事行里已有角标和状态文字），鼠标停上去带时刻
- 站点锁定：这一条锁的是"监控对象"，不是"这一页此刻的地址"。页面漂到别的网站，下一个刷新周期把它导航回来；同站（含子域登录跳转）正常跟随，任务记录的网址只在同站且不是登录页时才跟着更新。所以标签页被关掉后重开的仍是原页面，停在同站登录页期间也只是原地刷新，能不能回到原页由站点自己的重定向决定。代价是跨站登录（比如跳到别家账号域）时会被下一拍拽回来，正登到一半会被打断
- 自动重开与清理：误关监控中的标签页会自动在后台重新打开一张并继续任务；整扇窗口一起关掉、退出浏览器时不重开，交给启动恢复处理；任务没记着网址时也不重开，免得开出空白页。标签页确实失效或刷新失败时自动取消任务并通知
- 角标提示：工具栏图标显示监控数量；优先级从高到低是站点会话失效 `!`（红）、任务被异常自动暂停 `⚠`（橙）、全部暂停 `‖`（灰）、数量（蓝）。红那一格只认行为通道确认的掉线，见上面"盯住登录态"那一条
- 通知可点开、会自己收：关键词命中、任务自动停止、异常自动暂停、站点待重登这四类系统通知，点一下就跳到对应标签页并把它所在的窗口带到前台；同一张标签页上重新开始任务会收掉上一轮那三条，从暂停恢复收掉暂停那条。"站点待重登"那一条收掉的时刻是该页重新加载后不再落在登录页、或心跳回到 2xx（也就是行为通道认为会话回来了），不是站点告诉你登录成功了；站点没登录也回 200 时会提前收掉，纯靠票据消失识别出的那次掉线则不会自动收

## 安装方法

1. 下载最新 Release 的 zip 并解压，或克隆仓库：`git clone https://github.com/yrgpcn/tab-auto-refresh.git`
2. 打开 `chrome://extensions`，开启"开发者模式"
3. 点"加载已解压的扩展程序"，选择 `tab-auto-refresh/` 文件夹

## 安全说明

登录保持默认关闭。开启后，插件把监控站点的 cookie（含 HttpOnly 的登录票据）备份到本机的扩展存储 `chrome.storage.local`。这一层不加密：任何能读取浏览器配置目录的程序都能直接取走这些登录票据，安全性低于 Chrome 自身的加密 cookie 库。备份最多保留 20 个站点、30 天。请只在信任本机环境、且确有重启保登录需求时开启；不需要时保持关闭，关闭状态下不备份、不恢复，遗留备份也会被自动清除。

Webhook 通知默认关闭。开启后，每当所选事件发生，插件向你配置的 URL POST 一条 JSON，载荷里有被监控页面的地址、站点主机名、事件类型与时间戳，以及你填的关键词原文。地址只到 origin 与路径，查询参数一律剪掉：工单与后台系统这类网址常把一次性签名、会话令牌、邮箱手机号挂在 `?` 后面，而"跳回哪一页"并不依赖它们。关键词则刻意原样发出，因为"命中了哪个词"就是那条通知的内容本身。这意味着"你在监控哪些页面、盯的是哪些词"会披露给该端点以及链路上一切可见方，比如第三方消息服务的服务器。

还有一件容易忽略的事：你填的这个 webhook 地址本身就是一把凭据。这类地址通常内嵌 token，谁拿到就能往你的频道里发消息，而它和其他偏好设置一起存在 `chrome.storage.sync`，会随 Google 账号同步到你登录同一账号的每一台桌面 Chrome。请只配置你自己信任的端点，也别把这个地址贴到 issue 或截图里。不需要时留空即为彻底关闭，不建连、不发任何出站请求。

微信直连通知默认关闭。要留意的是凭据的存放位置：四项凭据随偏好设置存在 `chrome.storage.sync`，如果你登录了 Google 账号并开启同步，它们会同步到每一台登录同一账号的桌面 Chrome。其中 appsecret 是唯一一把能以该公众号名义发消息的钥匙，别贴到 issue 或截图里。弹窗里那一格不回显输入内容（圆点显示，粘贴照常），但掩码只挡得住屏幕旁边的眼睛，上面说的明文存放与跨设备同步一点都没因此改变。不需要时关掉开关即彻底停用，不发任何出站请求。

## 使用边界与验证

- 保活与心跳的前提：机器保持开机不休眠，浏览器保持开启。"不休眠"可以交给防系统休眠开关（`chrome.power`）代劳，有任务时自动阻止闲置睡眠；但"浏览器保持开启"是硬前提，脚本运行在页面里、心跳由浏览器发出，浏览器一关都随之停止。这种关机窗口只能靠登录保持在重启后恢复，两者互补
- 保活可能无效的场景：站点若校验事件的 `isTrusted`（拒绝程序合成事件），或在页面 `document.hidden` 时暂停心跳计时，或只把监听器挂在页面自己身上而收不到派发，注入的模拟活动就不起作用；静默心跳对把异常规律请求纳入风控的站点也可能无效。这类限制由对方服务器决定，绕不过去
- 验证墙只按标题与挑战子框架判断：整页挑战嵌在 iframe 里能检出，子框架里的挂件尺寸验证框被视口地板挡掉；普通页面加载验证服务脚本不算墙。误暂停时可点"恢复"，或关掉这一项（会停止探测并恢复因验证墙暂停的任务）
- 框架注入的边界：检测会试着把所有框架都取一遍，取到几个算几个；个别子框架进不去时结果只剩顶层那份，整页挑战在子框架里就检不到。只有整次注入被站点拒绝时才退回顶层重取一次
- 站点锁定的边界：如果你想在同一个标签页里手动换到别的网站，插件到刷新周期会把该标签页导航回原监控页面，这是设计使然。想更换监控对象，请先停止任务，再在新页面重新开启
- 验证方式：重新加载扩展（或加载最新 Release 的 zip），对某页面开启监控（间隔选 30 秒便于观察），在页面里点一个外部链接跳走，等下一次刷新，标签页会自动导航回原监控页面

## 技术栈

- Manifest V3（Chrome 扩展最新规范）
- Background Service Worker（后台定时任务）
- Chrome Extensions API（Alarms / Storage / Context Menus / Tabs / Cookies / Notifications / Scripting / Idle / Power）

## 项目结构

- `tab-auto-refresh/`：插件源码（manifest、后台、弹窗、微信直连配置教程页、共享逻辑、语言包、图标）。其中 `wechat-setup.html` 既是弹窗里"配置教程"指向的页面，也是仓库里的这份教程本身，同一份文件，不存在两处内容各自漂移
- `tests/`：纯逻辑单元测试
- `scripts/`：仓库校验与弹窗截图脚本
- `docs/`：README 用的截图等文档资源
- `.github/workflows/`：CI 与 tag 驱动的自动发布

## 开发与测试

- 仓库校验与单元测试：`node scripts/validate.mjs`、`node --test "tests/**/*.test.mjs"`，CI 自动执行。这两条不需要 `npm install`，脚本只用 Node 内置模块
- 弹窗截图：`scripts/screenshot-popup.mjs`，mock chrome API 后用本机 Chrome 渲染，一次写出 `docs/tab-auto-refresh/` 下的 `popup.png` 与 `popup-wechat.png`（README 顶部那两张）。需要本机 Chrome 与全局 playwright，CI 不跑
- 发布：改 `tab-auto-refresh/manifest.json` 版本号并更新 `CHANGELOG.md`，打 tag `tab-auto-refresh/vX.Y.Z` 并推送，Actions 自动打包并创建 GitHub Release，只保留最新 Release 与 tag
